# 发版指引（Release Runbook）

> **适用对象**：任何接手本仓库的编码 Agent 或维护者。功能开发完成、代码已提交后，按本文件可从零完成一次完整发版。
>
> **使用方式**：本文是**可机械执行的清单**，不是科普。每步都给出「命令 + 成功判据」，请逐步执行、逐步验证，不要跳步。
>
> **文档属性**：全部命令已在本仓库实测；不含任何个人信息（作者姓名、邮箱、账号）；仓库地址统一以 `<owner>/<repo>` 占位。
>
> 最后核对版本：`v1.6.0` 时期。

---

## 0. 先做决策：现在该发版吗？

| 情况 | 是否发版 |
| --- | --- |
| 有用户可见的新功能或缺陷修复 | ✅ 发版 |
| 仅文档 / CI / 注释 / 重构且无行为变化 | ❌ 不发（可并入下次） |
| 第 3 节质量门未全绿 | ❌ 禁止发版 |
| 只想让别人试用未发布代码 | ❌ 不要发版，用分支或 `pip install git+...` |

**版本号递增规则（SemVer，本仓库历史实践一致）**

| 变更性质 | 递增 | 示例 |
| --- | --- | --- |
| 仅修缺陷 | PATCH | `1.6.0` → `1.6.1` |
| 向后兼容地新增功能 | MINOR | `1.6.1` → `1.7.0` |
| 破坏性变更（CLI 参数、数据结构、分片格式等）| MAJOR | `1.7.0` → `2.0.0` |

**标签命名规范**：一律 `vX.Y.Z`（annotated tag），与 PyPI 版本号 `X.Y.Z` 对应（带 `v` 前缀 / 不带前缀的区别务必注意）。

## 1. 一次发版会产出什么

一次完整发版有**四条产物线**，其中只有前两条是自动的：

| # | 产物 | 生成方式 | 自动？ |
| --- | --- | --- | --- |
| 1 | PyPI 包（wheel + sdist） | GitHub Actions `publish.yml` | ✅ 自动 |
| 2 | GitHub Release（附 `dist/*` + 自动生成 release notes） | GitHub Actions（仅 tag 触发时） | ✅ 自动 |
| 3 | macOS 程序坞 `.app` | 本地 `bash macos/build_app.sh` | ❌ **手动**（CI 跑在 ubuntu，无法编译 Swift / 打包 .app） |
| 4 | 开发机本地命令（`pip install -e` + `~/.local/bin` 软链） | `bash install.sh` | ❌ 手动 |

> ⚠️ 常见误解：以为打了 tag 用户就能用上「新功能 + 新 App」。**macOS App 不在 CI 里构建**，必须在 macOS 上本地构建，且它与 PyPI 版本号是两条独立的线（但版本号要保持一致）。

## 2. 版本号：共 5 处，必须全部一致（★ 最易漏）

| # | 文件 | 位置 | 漏改的后果 |
| --- | --- | --- | --- |
| 1 | `pyproject.toml` | `version = "X.Y.Z"` | PyPI 发布**失败**（版本已存在）或发布成旧版本 |
| 2 | `myccusage_lib/__init__.py` | `__version__ = "X.Y.Z"` | `myccusage -v` 显示旧版本 |
| 3 | `myccusage_lib/macos/build_app.sh` | `<key>CFBundleShortVersionString</key>` 下一行 | 程序坞 App 的 Finder / 关于面板显示旧版本 |
| 4 | `myccusage_lib/macos/build_app.sh` | `<key>CFBundleVersion</key>` 下一行 | 同上（必须与第 3 处**完全相同**） |
| 5 | `myccusage_lib/web/static/index.html` | 页脚文本 `myccusage vX.Y.Z` | Web 看板左下角显示旧版本 |

### 一键校验（复制即用，非 0 退出码 = 不一致）

```bash
python3 - <<'PY'
import re, pathlib, sys

CHECKS = [
    ("pyproject.toml",                      r'^version\s*=\s*"([^"]+)"'),
    ("myccusage_lib/__init__.py",           r'^__version__\s*=\s*"([^"]+)"'),
    ("myccusage_lib/macos/build_app.sh",    r'<key>CFBundleShortVersionString</key>\s*<string>([^<]+)</string>'),
    ("myccusage_lib/macos/build_app.sh",    r'<key>CFBundleVersion</key>\s*<string>([^<]+)</string>'),
    ("myccusage_lib/web/static/index.html", r'myccusage v([0-9][^<\s]*)'),
]
found = []
for path, pat in CHECKS:
    m = re.search(pat, pathlib.Path(path).read_text(encoding="utf-8"), re.M)
    found.append((path, m.group(1) if m else None))
    print(f"  {'OK ' if m else 'MISS'} {path:40} {m.group(1) if m else '<未匹配>'}")

vers = {v for _, v in found if v}
ok = len(vers) == 1 and all(v for _, v in found)
print("  =>", "全部对齐: " + vers.pop() if ok else "❌ 版本号不一致或存在未匹配项，禁止继续发版")
sys.exit(0 if ok else 1)
PY
```

## 3. 发版质量门（必须全绿才可进入第 4 节）

### 3.1 语法与导入（每次必跑）

```bash
python3 -m compileall -q myccusage_lib && echo "语法 OK"
python3 -c "import myccusage_lib, myccusage_lib.core, myccusage_lib.sync, myccusage_lib.web.server; print('导入 OK')"
```

### 3.2 启动自检（每次必跑）

```bash
python3 -m myccusage_lib.cli --web --daemon --port 8899 --no-open &
sleep 3
for ep in /api/ping /api/agents /api/today /api/all /api/sync/status; do
  printf "  %-18s -> HTTP %s\n" "$ep" "$(curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8899$ep)"
done
kill %1 2>/dev/null
```

**成功判据**：5 个端点全部 `HTTP 200`。

### 3.3 数据链路一致性（**改动过 `core.py` 或 `sync.py` 时必跑**）

程序屋（`/api/today`）与 Web 看板（`/api/all`、`/api/data`）必须共用同一份口径。历史上二者曾因只给一半链路接入异机融合而长期不对齐。

```bash
python3 - <<'PY'
from myccusage_lib import core
q = core.get_today_quick_summary(force_refresh=True)
a = core.get_all_agents_summary(force_refresh=True)
d = q["totalTokens"] - a["today"]["totalTokens"]
print(f"  /api/today = {q['totalTokens']:,}   /api/all = {a['today']['totalTokens']:,}   差 = {d:,}")
print("  ✅ 口径一致" if abs(d) < 1_000_000 else "  ❌ 口径不一致，禁止发版")
PY
```

> 容差说明：活跃会话在两次调用之间仍会实时增长，允许极小差值；但**不允许出现百万级差异**。

### 3.4 同步分片健康度（**改动过 `sync.py` 时必跑**）

```bash
python3 - <<'PY'
import json, os
d = os.path.expanduser("~/.config/myccusage/sync_repo/devices")
if not os.path.isdir(d):
    print("  未启用多端同步，跳过"); raise SystemExit
shards = {}
for f in sorted(os.listdir(d)):
    if f.endswith(".json"):
        shards[f] = {a: v.get("dailyMap", {})
                     for a, v in (json.load(open(os.path.join(d, f))).get("agents") or {}).items()}
dup = 0
for i, (f1, s1) in enumerate(shards.items()):
    for f2, s2 in list(shards.items())[i+1:]:
        for aid in set(s1) & set(s2):
            for day in set(s1[aid]) & set(s2[aid]):
                dup += len({x.get("sessionId") for x in s1[aid][day]} &
                           {x.get("sessionId") for x in s2[aid][day]})
print(f"  跨设备重复 sessionId = {dup}")
print("  ✅ 分片互相隔离" if dup == 0 else "  ❌ 存在跨设备数据混入，禁止发版")
PY
```

**成功判据**：`跨设备重复 sessionId = 0`。若不为 0，先执行 `python3 scripts/repair_shard_provenance.py`（先试运行、确认明细、`--apply` 前会自动备份）。

## 4. 标准发版流程（Step by Step）

### Step 1 — 同步远端、确认工作区干净

```bash
git fetch origin && git status --short && git rev-parse --abbrev-ref HEAD
```

**成功判据**：当前分支为 `main`；`git status --short` 无输出（或仅有无需提交的忽略项）。

### Step 2 — 改齐 5 处版本号并校验

按第 2 节的表格逐处修改，然后跑第 2 节的一键校验。

**成功判据**：输出「全部对齐」。

### Step 3 — 本地预构建与校验

```bash
python3 -m pip install --upgrade build twine   # 需要 setuptools>=61（pyproject 已声明）
rm -rf dist build
python3 -m build                                # 产出 dist/myccusage-X.Y.Z-py3-none-any.whl 与 .tar.gz
python3 -m twine check dist/*
```

**成功判据**：`twine check` 对 wheel 与 sdist 均输出 `PASSED`。

再核对 wheel 内是否包含 macOS App 资源（这是本项目特有的打包要求，漏了会导致 pip 用户无法用 `dock` 命令）：

```bash
python3 -c "
import glob, zipfile
w = sorted(glob.glob('dist/*.whl'))[-1]
names = set(zipfile.ZipFile(w).namelist())
need = ['myccusage_lib/macos/main.swift','myccusage_lib/macos/build_app.sh','myccusage_lib/macos/generate_icon.py','myccusage_lib/macos/AppIcon.icns']
print(' ', w); [print(('  OK ' if n in names else '  MISS ') + n) for n in need]
print('  资源齐全:', all(n in names for n in need))
"
```

### Step 4 — 提交、打标签、推送（**此步触发 CI**）

```bash
git add -A
git commit -m "chore(release): bump version to X.Y.Z"
git tag -a vX.Y.Z -m "Release vX.Y.Z"
git push origin main
git push origin vX.Y.Z
```

**成功判据**：两次 push 均成功；`git ls-remote --tags origin | grep vX.Y.Z` 能查到。

> ❗ 推送标签**即等于发布**（不可逆地写入 PyPI），确认无误再执行第二条 push。

### Step 5 — 观察 CI 流水线

```bash
gh run list --limit 3
gh run watch            # 或 gh run view <run-id> --json jobs --jq '.jobs[].steps[] | "\(.name) -> \(.conclusion)"'
```

**成功判据**：`Publish to PyPI and GitHub Releases` 运行状态为 `success`，且各步骤结论均为 `success`。

### Step 6 — 发版后落地校验（**不要跳过**）

CI 变绿只代表「上传接口返回成功」，不代表用户此刻一定能装到。务必做用户视角校验：

```bash
# 6.1 版本端点（最直接）
curl -s https://pypi.org/pypi/myccusage/X.Y.Z/json | head -c 200

# 6.2 用户视角实测：能否真的下载安装（最关键）
pip download --no-deps --no-cache-dir -d /tmp/relcheck myccusage==X.Y.Z

# 6.3 GitHub Release 与附件
gh release view vX.Y.Z --json tagName,name,assets --jq '.tagName, (.assets | map(.name) | join(", "))'
```

**成功判据**：6.1 返回 JSON 含该版本；6.2 下载成功（`/tmp/relcheck` 出现 wheel）；6.3 列出 `myccusage-X.Y.Z-py3-none-any.whl` 与 `myccusage-X.Y.Z.tar.gz`。

> ⚠️ **已知坑**：聚合端点 `https://pypi.org/pypi/myccusage/json` 的 `info.version` 与 pip 的索引结果**可能滞后于实际发布状态**（受 CDN / 镜像源 / 网络代理缓存影响），曾观测到「版本端点返回 200 但 pip 仍拿不到该版本」的矛盾。因此：
> - 判定以 **6.2（pip 实测下载）** 为准；
> - 若 6.2 失败但 6.1 成功，先排除镜像源：`pip download -i https://pypi.org/simple --no-deps myccusage==X.Y.Z`；
> - 仍失败时，回看 CI 上传步骤日志是否有 `200 OK` 与 `View at: https://pypi.org/project/myccusage/X.Y.Z/`。

### Step 7 —（可选，仅 macOS）构建程序坞 App

```bash
bash macos/build_app.sh          # 根目录为转发壳，真实脚本在 myccusage_lib/macos/
open dist/myccusage.app          # 源码检出；pip 安装场景产物在 ~/Applications/
```

**成功判据**：输出「🎉 构建成功」；`dist/myccusage.app` 存在；启动后 Dock 出现常驻图标。

## 5. CI 流水线逐条说明（`.github/workflows/publish.yml`）

**触发条件**

- `push` 到匹配 `v*` 的标签 → 完整发布（含 GitHub Release）
- `workflow_dispatch`（网页手动触发）→ 构建并发布 PyPI，但 **`Create GitHub Release` 步骤带 `if: startsWith(github.ref, 'refs/tags/')`，手动触发时不会创建 Release**

**权限**：`contents: write`（创建 Release 用）。

**步骤**

| # | 步骤 | 作用 | 失败常见原因 |
| --- | --- | --- | --- |
| 1 | Checkout repository | 拉取源码 | — |
| 2 | Set up Python 3.12 | 固定发布环境 | — |
| 3 | Install build and packaging dependencies | `pip install build twine` | 网络异常 |
| 4 | Build sdist and wheel | `python -m build` | `pyproject.toml` 配置错误 / 版本号非法 |
| 5 | Verify distribution archives | `twine check dist/*` | README/元数据不合规 |
| 6 | Publish package to PyPI | 使用 Secret **`PYPI_API_TOKEN`** 上传 | Token 过期/缺失；**该版本号已存在** |
| 7 | Create GitHub Release | 上传 `dist/*` 为附件 + 自动生成 release notes | 标签非 `v*` 时该步不会执行 |

**前置条件（首次配置或换账号时必须确认）**：仓库 Settings → Secrets 中存在 `PYPI_API_TOKEN`，且该 Token 对目标 PyPI 项目有上传权限。

## 6. 失败与异常处理

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| CI 在 `Publish package to PyPI` 失败，提示版本已存在 | 该版本号已发布过，PyPI **不允许覆盖** | 递增版本号（如 `X.Y.Z` → `X.Y.Z+1`）后重走 Step 2 |
| CI 在 `Build sdist and wheel` 失败 | `pyproject.toml` 语法/字段问题 | 本地复现 `python3 -m build` 定位 |
| 用户装不到新版本 | 镜像源 / CDN 缓存 | 见 Step 6 的已知坑；用 `-i https://pypi.org/simple` 直连验证 |
| 标签打错（名字或指向的提交不对） | 人工失误 | 本地 `git tag -d vX.Y.Z` + 远端 `git push origin :refs/tags/vX.Y.Z` 后再重打；**仅在 CI 尚未发布成功时可行** |
| 已发布的版本有严重缺陷 | — | 在 PyPI 上 **Yank** 该版本（用户默认不再安装，但已安装的不受影响），然后立即发新补丁版本；**不可删除后复用同一版本号** |
| 忘记改 macOS App 版本号 | 见第 2 节 | 重新构建 App 即可（不影响 PyPI） |
